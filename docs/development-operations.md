# エージェント中心の開発オペレーション

Herdr の別ペインで Claude / Codex などを動かし、Neovim でコードを読み、依頼する場所を選び、成果を確認するための手順書。
エージェント本体は Neovim 内に開かない。

キーはプラグインの配布例ではなく、この dotfiles の設定に合わせている。

## 前提となるプラグイン

### Herdr 側

| プラグイン                                                                        | この手順書での役割                                                            |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| [ChmaraX/herdr-nvim](https://github.com/ChmaraX/herdr-nvim)                       | Neovim サイドバーの開閉、作業ファイルの候補表示、ファイルリンクからのオープン |
| [makyinmars/herdr-context.nvim](https://github.com/makyinmars/herdr-context.nvim) | Neovim 側と連携し、既定の送り先エージェントを選ぶポップアップを提供           |

管理対象は herdr-lazy 自身も含めて [plugins.list](../.config/herdr-lazy/plugins.list) に宣言する。herdr-lazy の初回導入は `herdr plugin install natori-hrj/herdr-lazy` で行う。

### Neovim 側

| プラグイン                                                                        | この手順書での役割                                                          |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| [ChmaraX/herdr-nvim](https://github.com/ChmaraX/herdr-nvim)                       | コードの行・選択範囲へのコメントと、コメント一式のエージェントへの受け渡し  |
| [makyinmars/herdr-context.nvim](https://github.com/makyinmars/herdr-context.nvim) | ファイル参照・選択コード・診断・quickfix の受け渡し、依頼文と添付内容の編集 |
| [eetann/editprompt.nvim](https://github.com/eetann/editprompt.nvim)               | プロンプト用バッファの送信、履歴、下書きの stash・復元                      |

| [nvim-neotest/neotest](https://github.com/nvim-neotest/neotest)                   | テストの実行と結果確認。Vitest・Python・Go のアダプターを設定済み           |

これらはこの dotfiles で設定済み。Herdr 関連の設定は [ai-agent.lua](../.config/nvim/lua/plugins/ai-agent.lua)、Hunk・Git 関連は [git.lua](../.config/nvim/lua/plugins/git.lua) にある。
同名の Herdr プラグインと Neovim プラグインは、それぞれ Herdr 側と Neovim 側を担当する別の導入先。

### プラグイン以外に使うもの

- [Herdr](https://herdr.dev)：エージェントを別ペインで動かす本体。
- [Neovim](https://neovim.io)：コードの閲覧・編集とプロンプト編集に使用。
- [editprompt CLI](https://github.com/eetann/editprompt)：mise で導入する本体。Herdr の編集ペイン起動と editprompt.nvim から利用する。
- [Hunk](https://www.hunk.dev/)：別ペインで起動する差分レビューツール。hunk-inline.nvim からコメントを扱う場合も必要。

## キーの読み方と操作する場所

| 表記                    | 操作                                          |
| ----------------------- | --------------------------------------------- |
| `prefix+l`              | Herdr で `Ctrl+B` を押して離し、`l`           |
| `prefix+Alt+e`          | Herdr で `Ctrl+B` を押して離し、`Alt+e`       |
| `<leader>ap`            | Neovim のノーマルモードで `Space` → `a` → `p` |
| `:HerdrContextQuickfix` | Neovim のコマンドラインで入力                 |
| `hunk diff`             | シェルで実行                                  |

Neovim の Visual 選択は、`v` または `V` で範囲を選んでからキーを押す。
Herdr 連携の Neovim プラグインは、`HERDR_ENV=1` の環境で有効になる。

## 作業ファイルを開く

**使う場面：** エージェントの作業後に、何を変更したか自分で読みたい。

1. 対象エージェントの Herdr ペインで `prefix+o` を押す。
2. ファイルの候補から選び、Enter を押す。
3. 横の Neovim でファイルを読む。行情報がある候補はその位置を開く。

候補画面は、文字を入力する前と後で探す範囲が変わる。

| 状態         | 候補                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| 検索文字なし | セッションで触ったファイルを新しい順に表示。セッションログの編集情報と Git の未コミット変更を利用する |
| 検索文字あり | リポジトリ全体のファイル名・パスをあいまい検索する。ファイル内容の検索ではない                        |

セッション情報を利用できない場合は、最近のペイン表示からファイルパスを抽出する経路もある。
初期候補の標準上限は20件。見つからなければ名前を入力して探す。

## リンクから開く

**使う場面：** 返答にある設定ファイルやコードへのリンクを、その場で読みたい。

1. Herdr 内のファイルリンクを `Ctrl+クリック` する。
2. サイドの Neovim で該当ファイルを確認する。

Herdr がクリックを受け、Herdr プラグイン `ChmaraX/herdr-nvim` の `open-link` に渡す。
この環境ではファイルパスと `file://` のリンクを受け取るハンドラーが有効。
行番号が渡された場合は、その位置を開く。

`prefix+o` は候補一覧から選ぶ操作、リンクのクリックは対象を直接指定する操作。
リンクとして扱われない表示や、クリックが端末に渡らない場合は `prefix+o` から探す。

## サイドバーを切り替える

**使う場面：** 横でコードを読みたい、またはエージェントの表示領域を広くしたい。

- `prefix+l`：Neovim サイドバーを出す／隠す。
- `prefix+o`：開くファイルを選ぶ。

サイドバーを隠しても、タブごとの Neovim はバッファやカーソル位置を保つ。
閉じていた Herdr タブ自体を破棄する操作とは別。

## コードを選んで依頼する

**使う場面：** 「この関数の責務を分けたい」「この条件分岐を説明してほしい」。

1. Neovim で対象箇所を開き、必要な範囲を選択する。
2. `<leader>ap` で、選択範囲を添えた依頼文の編集画面を開く。
3. 期待する動作、制約、確認してほしい点を書く。
4. 送り先と添付内容のプレビューを確認する。
5. `Ctrl+S` で依頼文を保持し、必要なら添付を調整する。
6. composer の `s` でエージェントの入力欄へ渡す。エージェント側で内容を確認し、Enter で実行する。

すぐ実行する場合は composer の `S` または `Ctrl+Enter` を使う。
端末で `Ctrl+Enter` を区別できなければ `Alt+Enter` を使う。
composer のキーは `?` で確認できる。

ファイル参照・選択したコード・診断だけを渡す場合は、下表の `<leader>ay` / `<leader>aY` / `<leader>ad` を使う。横で動いている Claude / Codex の、普段文章を打つ欄に内容が貼り付く。貼り付けただけではエージェントは動かない。その欄に「ここを修正して」などを書き足し、Enter を押すと依頼が送られる。

| Neovim のキー | 渡すもの                                 |
| ------------- | ---------------------------------------- |
| `<leader>ay`  | ファイルと行範囲の参照                   |
| `<leader>aY`  | 参照と選択したコード本文                 |
| `<leader>ad`  | 現在行・選択範囲の診断                   |
| `<leader>ac`  | 添付内容を集めて確認する composer を開く |

未保存のコードをそのまま伝えたいときは、composer の添付行で `e` を押して本文を含める。
ファイル参照だけを渡した場合、エージェントが読むディスク上の内容と未保存バッファの内容は異なる。

依頼例：

```text
この関数の入力チェックと永続化処理を分離したい。
公開APIとエラーの返し方は維持して、まず分け方を提案して。
```

## 行コメントをまとめて渡す

**使う場面：** 複数ファイルを読み、「ここを直してほしい」をまとめて返したい。

1. 気になる行、または Visual 選択上で `<leader>anc` を押し、コメントを書く。
2. 別の箇所にも同じ操作でコメントを追加する。
3. `<leader>anl` でコメント一覧を確認する。
4. `<leader>ans` でコメント一式をエージェントの入力欄へ渡す。
5. エージェント側で確認し、Enter で実行する。

入力欄で確認せず実行まで進める場合は `<leader>anS` を使う。
送り先が一意なら自動で選ばれ、複数候補がある場合は選択する。

コメントにはファイル・行番号とリポジトリ・ブランチ情報が付く。
コメントはメモリ上だけに保持され、標準では送信成功後にクリアされる。
長く残す判断・要件は Markdown に書く。

この行コメントは `herdr-nvim` の機能。後述の Hunk コメントとは別に管理される。

## 長いプロンプトを書く

**使う場面：** コード参照より、長文の指示そのものを編集したい。

### エージェントの入力欄から書き始める

Claude / Codex の入力欄で `Ctrl+G` を押すと、外部エディタで編集できる。
この dotfiles は `EDITOR=nvim` を設定済み。`VISUAL` が別途設定されていると、そちらが優先される場合がある。
保存してエディタを閉じ、エージェントの入力欄に戻って内容を確認する。

### Herdr の編集ペインを使う

1. 入力先にしたいエージェントのペインで `prefix+Alt+e` を押す。
2. editprompt の Neovim ペインで指示を書く。
3. `<leader>pI` で入力先に渡す、または `<leader>pi` で自動送信する。

| Neovim のキー               | 操作                             |
| --------------------------- | -------------------------------- |
| `<leader>pI`                | バッファを入力先へ渡す           |
| `<leader>pi`                | バッファを入力先へ渡して自動送信 |
| `<leader>pp` / `<leader>pn` | editprompt の履歴を前／次へ移動  |
| `<leader>pS` / `<leader>ps` | 下書きを stash／復元             |

**editprompt はプロンプト用バッファで使う。** 入力操作が成功すると、送ったバッファ内容をクリアする。
Visual 選択での `<leader>pi` / `<leader>pI` は、選択に触れる行を送った後、その行を削除する仕様。
ソースコードを渡すときは、元のコードを保持する Herdr context の `<leader>ay` / `<leader>aY` を使う。

## 診断と検査結果を渡す

**使う場面：** エージェントの修正を自分で検査し、失敗箇所を具体的に返したい。

1. Neovim で該当コードを開く。
2. `<leader>ts` で neotest のテスト一覧、または `<leader>tr` で Overseer のタスク選択を開く。
3. 対象のテスト・検査を実行し、結果を読む。
4. 診断なら `<leader>ad`、quickfix に入っている結果なら `:HerdrContextQuickfix` で入力欄へ渡す。
5. 再現条件と期待する動作を追記し、エージェント側で送信する。

neotest は Vitest / Python / Go のアダプターを設定済み。
Overseer のタスク候補や検査結果の取り込み方はプロジェクトに依存する。
すべてのテスト出力が自動で quickfix に入るわけではない。

quickfix にある問題を読むときは `:copen`、次へ `:cnext`、前へ `:cprevious`。
quickfix 内の `>` / `<` は quicker による周辺表示の展開／折りたたみ。

## Hunk でレビューする

**使う場面：** エージェントが作った変更全体を確認したい。

対象リポジトリのシェルで起動する。

```sh
hunk diff    # 作業ツリーの変更を見る
hunk show    # 直近コミットを見る
```

| Hunk のキー     | 操作                            |
| --------------- | ------------------------------- |
| `0` / `1` / `2` | 自動／unified／split 表示       |
| `s`             | ファイル一覧の表示切り替え      |
| `e`             | 選択ファイルを `$EDITOR` で開く |
| `q`             | 終了                            |

Hunk 自身の `diff` は未追跡ファイルも標準で含む。追跡済みだけなら `hunk diff --exclude-untracked`。

## Hunk と Neovim を往復する

**使う場面：** Hunk で見つけた疑問を、定義・参照・周辺コードまで調べたい。

1. Hunk で気になるファイルを特定する。
2. Herdr のファイルリンクや `prefix+o` から Neovim で開く。
3. LSP の定義・参照ジャンプなどで周辺を読む。
4. Hunk に指摘を残す場合は `<leader>hc` でコメントを追加する。
5. `<leader>hr` で Hunk コメント表示を更新する。
6. エージェントに「Hunk のコメントを確認して修正して」と依頼する。

これは `hunk-inline.nvim` と、起動中の Hunk セッションの連携。
Hunk にコメントを追加する操作だけでは、エージェントへの修正依頼は実行されない。
`<leader>hx` は Neovim 上のコメント表示を消す操作。
Hunk コメントは `BufEnter` / `FocusGained` でも取得する設定になっている。

Neovim で変更箇所を中心に読みたいときは `gz` で Git hunk 周辺への折りたたみを切り替えられる。

## 送り先を選ぶ

**使う場面：** 同じ workspace に Claude と Codex がいて、渡す相手を選びたい。

| 操作する場所 | キー                    | 操作                         |
| ------------ | ----------------------- | ---------------------------- |
| Neovim       | `<leader>at`            | Herdr context の送り先を選ぶ |
| Neovim       | `<leader>ar`            | Herdr context の状態を更新   |
| Herdr        | `prefix+,` / `prefix+.` | 前／次のエージェントへ移動   |
| Herdr        | prefix → バッククォート | 前のペインへ戻る             |

Herdr context の送り先選択と、herdr-nvim の行コメントの送り先選択は別機能。
片方で選んだからといって、もう片方にも同じ相手が設定されたとは考えず、表示された送り先を確認する。

## ひと仕事の流れ

例：エージェントの実装を確認し、2箇所の修正を返す。

1. Herdr のエージェントに実装を依頼する。
2. 完了後に `prefix+o` → 最新の変更ファイルを選ぶ。
3. Neovim で読み、疑問のある2箇所に `<leader>anc` でコメントを書く。
4. `<leader>anl` で一覧を確認し、`<leader>ans` で入力欄へ渡す。
5. エージェント側で送信し、修正を待つ。
6. テストを実行し、Hunk で差分全体を確認する。
7. 必要ならリンクから Neovim に戻り、周辺を調べる。

## 困ったとき

| 症状                                               | 対処                                                                                                      |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `prefix+o` に目的のファイルがない                  | 名前を入力してリポジトリ全体を検索する。対象エージェントのペイン・リポジトリが正しいか確認する            |
| リンクを押しても開かない                           | `Ctrl+クリック` を試す。開かなければ `prefix+o` から名前で検索する                                        |
| サイドの Neovim を隠したい                         | `prefix+l`。Neovim を終了しなくてもよい                                                                   |
| コンテキストを渡したのにエージェントが動かない     | 標準は入力欄への挿入だけ。エージェント側で Enter、または composer の `S` で実行する                       |
| エージェントによるファイル変更がバッファに見えない | 未保存変更の有無を確認して `:checktime`。未保存変更がある場合は自分の編集と外部変更を確認してから反映する |
| Hunk コメントが見えない                            | Hunk を起動して対象リポジトリのレビューを開き、Neovim で `<leader>hr`                                     |
| Herdr context で送り先が見つからない               | `<leader>ar` で更新。`:checkhealth herdr-context` で接続・環境・プラグイン状態を確認する                  |
| Neovim 側のキーが効かない                          | ノーマルモードと `Space` leader を確認。Herdr 内で起動しているか、プラグインがロードされているか確認する  |
