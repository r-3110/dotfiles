# OMC・OMX で自律的な作業を始める

Herdr の別ペインでエージェントを動かし、要件整理・実装・テスト・レビューを継続して進めてもらうための手順。

## どちらを使うか

| 使うエージェント | 使うもの                | シェルでの起動                        |
| ---------------- | ----------------------- | ------------------------------------- |
| Claude Code      | OMC（oh-my-claudecode） | `omc --plugin-dir "$OMC_PLUGIN_ROOT"` |
| Codex            | OMX（oh-my-codex）      | `omx`                                 |

シェルでエージェントを起動してから、そのエージェントの入力欄にモード名と依頼を書く。
`$autopilot` などの `$` 付きの指定は Codex の入力欄に書く。シェルには入力しない。
Claude Code では `/oh-my-claudecode:autopilot` のようにスラッシュコマンドで指定する。

## やりたいことから選ぶ

| やりたいこと                               | OMC / Claude Code             | OMX / Codex                       |
| ------------------------------------------ | ----------------------------- | --------------------------------- |
| 要件整理から実装・検証まで一通り任せる     | `/oh-my-claudecode:autopilot` | `$autopilot`                      |
| 決まった修正を、検証しながら完了まで進める | `/oh-my-claudecode:ralph`     | 承認済み計画を添えて `$ultragoal` |
| 実装前に計画だけ確認したい                 | `/oh-my-claudecode:ralplan`   | `$ralplan`                        |
| 複数段階の作業を、進捗を記録しながら進める | `/oh-my-claudecode:ultragoal` | `$ultragoal`                      |
| 動いているモードを中止する                 | `/oh-my-claudecode:cancel`    | `$cancel`                         |

最初は `autopilot` を使う。既に計画を確認してある場合は、その計画を指定して実行を依頼する。
計画だけのモードと、コードを書いて検証するモードは別。

## 最初から一通り任せたい

### Claude Code で始める

1. 対象プロジェクトのディレクトリで起動する。

   ```sh
   omc --plugin-dir "$OMC_PLUGIN_ROOT"
   ```

2. Claude Code の入力欄に依頼を書く。

   ```text
   /oh-my-claudecode:autopilot
   商品一覧に検索機能を追加したい。
   商品名で部分一致検索でき、検索語を消すと全件に戻ること。
   既存のAPIと画面構成に合わせ、実装・テスト・レビューまで進めて。
   ```

3. 要件や選択肢を質問されたら回答する。
4. 作業中に判断が必要になったら回答し、完了報告でテスト結果と残件を確認する。

OMC の autopilot は、要件整理 → 計画 → 実装 → テストと修正 → レビューの順で進める。
同じ検査エラーが繰り返される場合などは、原因を報告して止まることがある。

### Codex で始める

1. 対象プロジェクトのディレクトリで起動する。

   ```sh
   omx
   ```

2. Codex の入力欄に依頼を書く。

   ```text
   $autopilot
   商品一覧に検索機能を追加したい。
   商品名で部分一致検索でき、検索語を消すと全件に戻ること。
   既存のAPIと画面構成に合わせ、実装・テスト・レビューまで進めて。
   ```

3. 最初の要件確認の質問に回答する。
4. 計画について判断を求められたら確認し、その後の実装・検証を進めてもらう。

OMX の autopilot は次の3段階を順番に進める。

| 段階           | エージェントがすること                           | ユーザーがすること                                 |
| -------------- | ------------------------------------------------ | -------------------------------------------------- |
| deep-interview | 目的・制約・完了条件を質問して整理する           | 質問に回答する                                     |
| ralplan        | 実装計画を作り、設計・レビューの観点から確認する | 判断や確認を求められた場合に回答する               |
| ultragoal      | 計画を分割して実装し、検証とレビューを進める     | 承認が必要な操作や、外部情報が必要な場面に対応する |

OMX の autopilot は、開始直後から完全に放置する使い方には向かない。最初の要件確認に回答してから任せる。

## 何を書いてから任せるか

実装方法を細かく指定するより、何ができれば完了かを書く。

```text
目的：
やってほしいこと：
完了条件：
守ってほしい制約：
確認方法：
判断が必要なら聞いてほしいこと：
```

例：

```text
目的：ログイン後に元のページへ戻れるようにしたい。
やってほしいこと：未ログインで商品詳細を開いたときの遷移を直す。
完了条件：ログイン後、最初に開こうとした商品詳細が表示される。
守ってほしい制約：既存の認証方式と公開APIは維持する。
確認方法：関連テストと、未ログインからの遷移を確認する。
判断が必要なら聞いてほしいこと：仕様変更が必要な場合。
```

Neovim でコードを選んで依頼を作る場合は、[開発オペレーション](development-operations.md#コードを選んで依頼する)の方法でモード名と依頼文を渡す。

## 決まった修正を完了まで進めたい

### Claude Code：Ralph

Claude Code の入力欄に書く。

```text
/oh-my-claudecode:ralph
ログイン後の戻り先が失われる不具合を修正して。
未ログインで開いた商品詳細にログイン後戻れることを完了条件にする。
関連テストを追加し、既存テストも確認して、レビュー指摘の解消まで進めて。
```

Ralph は作業を項目に分け、完了条件に沿って修正・検証を繰り返す。
テストやレビューが通ることを確認して完了を判断するモードであり、成功を無条件に保証するものではない。

### Codex：承認済みの計画を Ultragoal で実行

Codex の入力欄に書く。計画ファイルのパスは実際のものに置き換える。

```text
$ultragoal
docs/login-redirect-plan.md の承認済み計画を実行して。
完了条件に沿って実装・テスト・レビューを進め、進捗と検証結果を記録して。
```

計画がまだない場合は、先に `$autopilot` を使うか、`$ralplan` で計画を確認する。
Ultragoal は作業ごとの進捗と検証結果を記録しながら進める。

## 計画を見てから実装を任せたい

1. エージェントの入力欄で計画を依頼する。

   Claude Code：

   ```text
   /oh-my-claudecode:ralplan
   商品検索の追加方法を計画して。まず計画だけを確認したい。
   ```

   Codex：

   ```text
   $ralplan
   商品検索の追加方法を計画して。まず計画だけを確認したい。
   ```

2. 対象範囲、完了条件、テスト方法を確認して修正を伝える。
3. 内容が決まったら、実装を明示的に依頼する。

   Claude Code：

   ```text
   /oh-my-claudecode:autopilot
   今確認した計画に沿って、実装・テスト・レビューまで進めて。
   ```

   Codex：

   ```text
   $ultragoal
   今確認した計画に沿って、実装・テスト・レビューまで進めて。
   ```

## 長い作業を複数段階に分けたい

移行や大きな機能追加では、Ultragoal で完了条件と進捗をファイルに残せる。

| 環境        | 入力欄での指定                       | 進捗記録の基本配置 |
| ----------- | ------------------------------------ | ------------------ |
| Claude Code | `/oh-my-claudecode:ultragoal` と依頼 | `.omc/ultragoal/`  |
| Codex       | `$ultragoal` と承認済み計画          | `.omx/ultragoal/`  |

Claude Code の Ultragoal は、ユーザー自身が Claude Code の入力欄に `/goal ...` を入力する必要がある。
エージェントから具体的な `/goal` の指示が出たら、その内容を確認して入力する。
シェルの `omc ultragoal` コマンドだけでは Claude Code の `/goal` は開始しない。

Codex の Ultragoal は、利用可能な goal ツールと進捗記録を連携させて進める。
進捗ファイルを作っただけでは実装が始まったことにならないため、エージェントに実行まで依頼する。

## 途中で状況を知りたい・方針を変えたい

動いているエージェントの入力欄へ、具体的に伝える。

```text
完了したこと、残っていること、今止まっている理由を教えて。
```

```text
公開APIは変えない方針に修正して。その制約を計画と完了条件に反映して続けて。
```

同じセッションで継続するときは、次のように伝える。

```text
保存済みの計画と進捗を確認して、未完了のところから続けて。
```

中止済みのモードを再開する場合は、保存済み計画を指定して、使うモードと再開する意思を明示する。
ファイルに残る計画・進捗と、会話セッションの状態は別。新しいセッションでは引き継ぐファイルを伝える。

## 作業を止めたい

1. ツール実行や応答をまず中断したい場合は `Ctrl+C`。
2. 入力できる状態で、動いているモードの中止を依頼する。

   Claude Code：

   ```text
   /oh-my-claudecode:cancel
   ```

   Codex：

   ```text
   $cancel
   ```

3. モードが中止された報告を確認する。

`Ctrl+C` で実行を中断する操作と、継続モードを中止する操作は別。
中止しても、既に書き換えたコードが元に戻るわけではない。

## 並列作業も任せたい

複数担当で進めたい場合は、依頼に「独立した作業はチームで並列に進めて」と添える。
チームの明示的な指定は OMC の `/oh-my-claudecode:team`、OMX の `$team` を使う。

この dotfiles は OMC・OMX のチーム実行先を Herdr に設定している。
担当は別タブに開く。通常の自律実行を始めるだけなら、先に Team を手動起動する必要はない。
OMX の Herdr チーム起動は担当用 worktree を作るため、クリーンな Git 作業ツリーを用意する。
チーム起動の詳細は [Herdr で OMC / OMX を使う](../nix/agent-teams/README.md)を参照する。

## 完了報告で確認すること

- 指定した完了条件を満たしているか。
- どのテスト・検査を実行し、何が成功・失敗したか。
- 未確認の項目や、外部要因で止まっている作業がないか。
- 変更差分を Hunk や Neovim で確認できるか。

自律実行でも、確認質問・操作の承認・外部サービスの認証でユーザーの応答が必要になる場合がある。
モードを始めることと、権限を広げることは別。
